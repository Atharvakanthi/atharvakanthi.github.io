Data Analyst Agent

A multi-agent framework I designed that turns a business enquiry into a finished, reviewed market report. Each stage of an analyst's job is handled by a specialist agent, and every error is routed back to the agent that made it.

Architecture

How a report gets made

Follow the line: an enquiry goes in at the top and a reviewed report comes out of the bottom. The dashed red path is the feedback loop that makes the output trustworthy.

Roles

What each agent does

AgentJob
IntakeReads the enquiry, works out what it is asking, and breaks it into predefined analysis buckets. The buckets become the report template.
Data retrievalSearches the internal database for each bucket. Where data is missing, it sends a request to the data-collection system and waits for the data to come back.
Data analystCleans and standardises the data and runs the analysis: segmentation, benchmarks, distributions, trends.
Business analystChecks the output against the business requirement and reshapes it into what the reader needs to decide.
ReviewerReviews the analysis for errors and gaps before anything is designed.
DesignerBuilds the report: layout, charts, maps and tables.
Design reviewerChecks that every element has rendered correctly.
Final review x3Three separate rounds that read the whole report with its graphs and confirm it is correct. Any problem is sent back to the agent responsible.

Design choices that mattered

Buckets before data. The intake agent turns an open question into a fixed set of analysis buckets. That keeps reports comparable across locations and tells the retrieval agent exactly what is missing, instead of fetching data speculatively.

Review is separate from creation. The agent that wrote a number never checks it. A reviewer reads the analysis, a design reviewer checks rendering, and three final rounds read the finished report page by page. Errors go back to the agent responsible, so the system learns where it fails.

Missing data is a request, not a gap. When the internal database cannot fill a bucket, retrieval raises a data-collection request and waits. Reports are never padded with assumptions where evidence could be collected.

Example output

The Athimuthlu location report was produced end to end by this system: a location and regulatory profile, a competitive benchmark across three corridors, resale and short-stay analysis, and a build-versus-buy economic comparison. This version has client details removed and figures shown as indices and percentages.
